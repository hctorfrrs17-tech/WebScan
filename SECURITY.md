# Security Policy

## Reporting a vulnerability

Please do not disclose a suspected WebScan vulnerability in a public issue, pull request, discussion, or social post. Send a concise report to **hctor.tech@outlook.com** with a description of the issue, affected version or commit, reproduction conditions, expected impact, and any suggested mitigation.

The project will acknowledge a good-faith report, investigate it, and coordinate a fix before public disclosure whenever possible.

## Scope of the application

WebScan must remain defensive and authorization-gated. The project does not accept contributions that add credential attacks, exploit automation, unauthenticated access-control bypasses, brute force, fuzzing against third-party targets, denial-of-service testing, stealth features, or scanning of local/private network addresses.

Security researchers may test only their own local copy of WebScan or an environment they are explicitly authorized to test. Do not test the public demo or any deployed instance with techniques that could affect availability or other users.
